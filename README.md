# Суфлёр

Помощник сотрудника телеком-розницы: короткая подсказка, карточка клиента и чат с раскрываемыми источниками. Отдельная административная часть управляет знаниями, процессами, каталогом, моделями и командой.

## Быстрый просмотр

Нужны Node.js 24 и pnpm 9.15.1:

```sh
pnpm install --frozen-lockfile
cp .env.example .env
pnpm dev
```

Откройте **http://localhost:3000/app**, админка — **http://localhost:3000/admin**. Не заменяйте существующий `.env`, если уже заполнили его.

`DEMO_MODE=true` — явно обозначенная учебная среда. Шесть вымышленных документов, пример разговора, ручной ввод, переключение модели, чат и редактирование базы работают без ключей. Данные живут в памяти и сбрасываются при перезапуске API. В демо нет аутентификации, микрофон не записывается, вызовы KEV/Qwen/Kimi не имитируются как реальные: используется детерминированный учебный сценарий. PDF/DOCX требуют настоящего сервиса обработки.

Тот же просмотр в production-сборке Docker:

```sh
docker compose -f compose.demo.yml up --build -d
```

Откройте **http://localhost:8080/app**. Порт привязан только к localhost. Остановить: `docker compose -f compose.demo.yml down`.

## Реальный режим

1. Создайте отдельное окружение: `pnpm setup:env`. Команда создаст `.env.production.local` с правами `0600`, случайными инфраструктурными секретами и без перезаписи существующего файла.
2. Впишите `OPENROUTER_API_KEY`, `MISTRAL_API_KEY`, `HF_TOKEN`. Для `pyannote/segmentation-3.0` нужен доступ к модели в Hugging Face. Установите `APP_ORIGIN` в точный адрес приложения, локально — `http://localhost:8080`.
3. Запустите инфраструктуру и сервисы:

```sh
docker compose --env-file .env.production.local up --build -d
```

Миграции Better Auth и таблицы приложения применяются отдельным сервисом `migrate`. MinIO получает закрытый бакет `sufler`. Первый запуск Python-сервисов скачивает веса моделей; потребуется несколько гигабайт и время на прогрев. CPU-образы Python зафиксированы для Linux amd64; на Apple Silicon они работают через эмуляцию. Начальная оценка ресурсов для полного стенда — 16 ГБ RAM и 20 ГБ свободного места, затем подберите их по измерениям.

4. Локально заполните в `.env.production.local` поля `BOOTSTRAP_EMAIL`, `BOOTSTRAP_NAME`, `BOOTSTRAP_PASSWORD` (от 12 символов), `BOOTSTRAP_ORG`, затем:

```sh
docker compose --env-file .env.production.local run --rm \
  --env-from-file .env.production.local api node dist/cli.js bootstrap
```

`--env-from-file` требует свежий Docker Compose. Универсальный вариант — передать эти четыре переменные через окружение shell и `run -e BOOTSTRAP_EMAIL -e BOOTSTRAP_NAME -e BOOTSTRAP_PASSWORD -e BOOTSTRAP_ORG`. Не передавайте пароль строкой команды и не коммитьте заполненный env. После настройки удалите значение `BOOTSTRAP_PASSWORD` из файла. Команда не перезаписывает существующие аккаунты.

5. Войдите в `/admin/login`, добавьте личные аккаунты консультантов, загрузите документы, проверьте извлечённые фрагменты, зависимости шагов, даты и регион и нажмите «Опубликовать». Реальная организация создаётся с пустой базой. В `/admin/models` проверьте нужные модели и разрешите их сотрудникам.
6. На `/app` выберите направленный микрофон и запишите 25 секунд своего голоса. Нужно не менее 8 секунд чистой речи. После этого включите микрофон для консультации.

Проверка подключений:

```sh
docker compose --env-file .env.production.local exec api node dist/cli.js check
```

Для разработки вне Docker можно установить `DEMO_MODE=false` в `.env`, настроить доступные локально PostgreSQL/Redis/S3/Python-сервисы и выполнить `pnpm db:migrate`, `pnpm bootstrap`, `pnpm dev`.

## Что делает система

- AudioWorklet отправляет PCM 16 кГц через авторизованный WebSocket. Сервис речи сначала назначает говорящего через Diart + pyannote/WeSpeaker; затем передаёт его фрагмент в Voxtral Realtime. Неопределённый голос требует подтверждения. Перекрытия исключаются из контекста.
- KEV получает ограниченный контекст и справочник опубликованных намерений через OpenRouter Decisions. Его оценки превращаются в проверяемый patch. Низкая уверенность или отказ KEV включают резервный Qwen; точные значения извлекаются Qwen со ссылкой на цитату.
- PostgreSQL хранит карточку и ревизии. Redis хранит короткий кэш; BullMQ обрабатывает документы и удаляет разговоры старше 30 дней. Поздние ответы проверяются по ревизии и эпохе генерации.
- Weaviate ищет по тексту и векторам BGE-M3; BGE-reranker-v2-m3 отбирает фрагменты. Поиск ограничен организацией, версией, датами и регионом.
- Выбранная Qwen/Kimi возвращает только ID фрагментов. Сервер повторно проверяет источник и подтверждённые зависимости шагов, затем выводит **дословный утверждённый текст**. Произвольная генерация модели сотруднику не показывается. Для чата действует тот же путь.
- Модель подсказок меняется без потери карточки. Незавершённая генерация отменяется. Классификатор и его резерв настраиваются отдельно через `KEV_MODEL`, `CLASSIFIER_FALLBACK_MODEL`, `KEV_CONFIDENCE_THRESHOLD`.
- «Новый клиент» завершает прежний разговор и создаёт пустую карточку. Голосовые профили посетителей существуют только внутри аудиосессии. Образец консультанта хранится как вектор в RAM до 12 часов.
- В Chrome на компьютере кнопка «Поверх окон» открывает Document Picture-in-Picture. Основная вкладка должна оставаться открытой. На телефоне используется адаптивная страница; постоянная фоновая запись мобильным браузером не обещается.

## Проверки

```sh
pnpm typecheck
pnpm test
pnpm test:integration   # нужен Docker; временный PostgreSQL удаляется автоматически
pnpm build
python3 -m py_compile services/speech/main.py services/knowledge/main.py
```

Интеграционный тест запускает скомпилированный NestJS API и настоящий PostgreSQL: миграции, bootstrap, вход по паролю, запрет регистрации, роли, две организации, Origin и WebSocket. Обычные тесты проверяют источники, даты, обязательные шаги, отмену поздних ответов, смену клиента/модели, лимит десяти диалогов и retention.

Отдельная проверка настоящего Weaviate использует фиксированные тестовые векторы, без скачивания BGE. Она проверяет создание схемы, индексацию и фильтры организации, версии и региона, но не качество семантического поиска:

```sh
docker build --platform linux/amd64 -f services/knowledge/Dockerfile -t sufler-knowledge:test .
pnpm test:rag:integration
```

Временный Weaviate и тестовая Docker-сеть удаляются после проверки. Образ обработчика можно переопределить переменной `KNOWLEDGE_TEST_IMAGE`.

Локальная проверка реализации: 32 теста TypeScript, проверка типов, интеграции с PostgreSQL и Weaviate, production-сборка Next.js/NestJS в Docker и импорты Python-зависимостей. Десктопный и мобильный интерфейсы проверены в браузере. Для совместимости с pyannote.core 5 версия Matplotlib зафиксирована отдельно. Реальные облачные вызовы и акустическое качество в этот прогон не входят.

`pnpm eval test pipeline` — отдельный прогон реальных классификаторов с ключом OpenRouter. `eval/ru-cases.json` — небольшой **синтетический регрессионный набор**, разделённый на calibration/test; это не полноценная проверка качества на розничных разговорах. Режимы `pnpm eval calibration kev`, `pnpm eval test kev` и `pnpm eval test qwen` позволяют сравнивать классификаторы отдельно, не смешивая калибровку и итоговую оценку. Вызовы платные по тарифу провайдера.

Перед пилотом нужны записи с шумом, сопровождающими, перебиваниями и сменой посетителя; независимый русский test set; измерения KEV и резервного Qwen, выбора источников, доли отказов, времени от конца речи и от подтверждённой реплики. Цели 10 разговоров и p95 ≤ 6 секунд **не являются уже измеренным результатом**. Порог сходства голоса 0.65 и KEV 0.85 — стартовые параметры для калибровки.

## Устройство репозитория

| Путь | Содержимое |
| --- | --- |
| `apps/web` | Next.js, shadcn/ui, AI Elements, PiP, AudioWorklet |
| `apps/api` | NestJS, Better Auth, AI SDK, KEV, RAG, REST/WS, очереди |
| `packages/shared` | Zod-контракты, ревизии и проверка источников |
| `services/speech` | Diart, pyannote, WeSpeaker, Silero VAD, Voxtral |
| `services/knowledge` | Docling, BGE-M3, reranker, Weaviate |
| `tests` | Доменные, асинхронные и интеграционные проверки |
| `deploy/fly` | Конфигурации пяти приложений Fly.io |

Для небольшого VPS **4 CPU / 8 ГБ RAM** предусмотрен `compose.coolify.small.yml`: одна аудиосессия, multilingual E5-small, гибридный поиск без тяжёлого reranker, PDF/DOCX без OCR. Аудиозапись выключена, история хранится 7 дней; параметры можно изменить через env. Для Coolify укажите `/compose.coolify.small.yml`. Полный профиль `compose.coolify.yml` сохраняет BGE-M3/reranker/Docling и требует больше ресурсов.

Подробности: [архитектура и границы пилота](docs/architecture.md), [развёртывание в Coolify и на Fly.io](docs/deployment.md).
